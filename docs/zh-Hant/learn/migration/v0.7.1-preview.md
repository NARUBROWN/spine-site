# 移轉至 v0.7.1 處理器輸入

::: info
本頁記錄 0.7.1 當時行為與移轉歷史。目前輸入、上下文與驗證請參考 [0.7.5 移轉指南](/zh-Hant/learn/migration/v0.7.5)。
:::


在 Spine `v0.7.1` 中，可透過依來源劃分的結構體接收路徑、查詢和標頭並直接存取欄位。本指南說明移轉步驟與繫結差異。`query.Values`、`header.Values`、`query.Pagination` 和舊 `path` 包裝型別保留但已棄用，不能在同一處理器中與新的 Path、Query 或 Header 輸入混用。

## 適用版本 {#versions}

以下獨立範例使用正式版核心 `v0.7.1`、Echo `v0.2.0` 和 playground `v0.2.0`。核心和 Echo 需要 Go 1.25.5 以上版本，playground 需要 Go 1.26 以上版本。建立 Go 模組，安裝相依套件並保留 `go.mod` 和 `go.sum`。

```bash
go get github.com/NARUBROWN/spine@v0.7.1 github.com/NARUBROWN/spine-echo-platform@v0.2.0 github.com/NARUBROWN/spine-validator-playground@v0.2.0
```

未註冊 validator 時仍會進行型別轉換，但不會檢查 `validate` 標籤，OpenAPI 只提供以路徑為中心的資訊。如需畫面，請另行啟用 [OpenAPI UI 設定](/zh-Hant/reference/api/openapi#tools)。

## 原有參數與新 DTO 的對應關係 {#mapping}

| 原有輸入 | 新輸入 | 在處理器中讀取的方式 |
| --- | --- | --- |
| `id path.Int` 與 `id.Value` | `id input.Path[int64]` | `*id` |
| `path.String`、`path.Boolean` | `input.Path[string]`、`input.Path[bool]` | 解參考指標 |
| `q query.Values` | `q input.Query[UserQuery]` | `q.Page`、`q.Tags` |
| `page query.Pagination` | Query DTO 的 `Page`、`Size` 欄位 | 缺少時由應用程式設定預設值 |
| `headers header.Values` | 帶有 `header` 標籤的 `*UserHeaders` | `headers.RequestID` |
| 原有本文 DTO | `body input.Body[UpdateBody]` | `body.Name` |

路徑、查詢和標頭分別接收。`input.Path[int64]` 等純量依路由變數順序對應，`input.Query[T]` 的無標籤欄位使用 lowerCamel 名稱。v0.7.1 沒有 `input.Header`，標頭使用帶 `header` 標籤的獨立結構體指標。一般結構體指標依標籤推斷來源的方式仍受支援。

## 新處理器的完整範例 {#example}

以下是獨立參考應用程式的 `main.go`，可用來同時檢查輸入宣告與行為。對於既有應用程式，請將 DTO、處理器與啟動設定整合至目前的 composition。

```go
package main

import (
    "log"

    "github.com/NARUBROWN/spine"
    echoplatform "github.com/NARUBROWN/spine-echo-platform"
    playground "github.com/NARUBROWN/spine-validator-playground"
    "github.com/NARUBROWN/spine/pkg/api"
    "github.com/NARUBROWN/spine/pkg/boot"
    "github.com/NARUBROWN/spine/pkg/constructor"
    "github.com/NARUBROWN/spine/pkg/httpx"
    "github.com/NARUBROWN/spine/pkg/input"
)

type UserQuery struct {
    Page *int
    Size *int
    Tags []string
}

type UserHeaders struct {
    RequestID string `header:"X-Request-ID" validate:"required"`
    Host      string `header:"Host"`
}

type UpdateBody struct {
    Name  string `json:"name" validate:"required"`
    Count int    `json:"count" validate:"gte=0"`
}

type UserView struct {
    ID        int64    `json:"id"`
    Name      string   `json:"name"`
    Count     int      `json:"count"`
    Page      int      `json:"page"`
    Size      int      `json:"size"`
    Tags      []string `json:"tags"`
    RequestID string   `json:"request_id"`
    Host      string   `json:"host"`
}

type UserController struct{}

func (*UserController) Constructor() *UserController { return &UserController{} }

func (c *UserController) RegisterRoutes(r *api.Registry) {
    r.POST("/users/:user_id", func(body input.Body[UpdateBody], id input.Path[int64], q input.Query[UserQuery], headers *UserHeaders) httpx.Response[UserView] {
        return c.Update(body, id, q, headers)
    })
}

func (*UserController) Update(body input.Body[UpdateBody], id input.Path[int64], q input.Query[UserQuery], headers *UserHeaders) httpx.Response[UserView] {
    page, size := 1, 20
    if q.Page != nil {
        page = *q.Page
    }
    if q.Size != nil {
        size = *q.Size
    }
    return httpx.Response[UserView]{Body: UserView{
        ID: *id, Name: body.Name, Count: body.Count,
        Page: page, Size: size, Tags: q.Tags,
        RequestID: headers.RequestID, Host: headers.Host,
    }}
}

func main() {
    engine, err := playground.New()
    if err != nil {
        log.Fatal(err)
    }
    app := spine.New(echoplatform.Option(), spine.WithValidator(engine))
    app.Constructor(constructor.Controller(&UserController{}))
    options := boot.Options{
        Address: ":8080",
        EnableGracefulShutdown: true,
        HTTP: &boot.HTTPOptions{
            OpenAPI: boot.OpenAPIOptions{Enabled: true},
        },
    }
    if err := app.Run(options); err != nil {
        log.Fatal(err)
    }
}
```

輸入是否必填由已註冊 validator 的契約決定。上例中的 `Name` 與 `RequestID` 透過 `validate:"required"` 宣告為必填，不會僅根據是否為指標決定。`Page` 與 `Size` 使用指標來區分缺少值和實際數字 `0`。正數、最大值等規則需要由應用程式另外向 validator 宣告。

固定相依套件版本並套用程式碼後，在專案根目錄執行。參考應用程式可以單獨執行該檔案；既有應用程式則使用目前的進入點。

```bash
go mod tidy
go run main.go
```

## 逐一完整移轉處理器 {#compatibility}

| 組合 | v0.7.1 處理方式 |
| --- | --- |
| 僅使用原有輸入 API | 保留 Deprecated 簽名，Pagination 的 page/size 重複時回傳 HTTP 400 |
| 原有輸入與原有本文 DTO 或 context | 繼續支援 |
| 新 Path、Query、Header DTO 與本文 DTO 或 context | 支援 |
| 在同一處理器中混用 Deprecated 輸入與新 Path、Query、Header DTO | 即使來源不同，也拒絕啟動 |
| 在不同處理器中分別使用原有 API 與新 DTO | 支援 |

例如，不能只將路徑改為 `input.Path[int64]`，卻在同一處理器中保留 `query.Values` 或 `query.Pagination`。請一起移轉該處理器的所有 Deprecated 輸入參數。`context.Context` 與控制器情境不屬於 Deprecated 輸入，可以繼續注入。

混用新 Path DTO 與原有 path 包裝型別時，錯誤為 `HTTP_PATH_INPUT_MIXED`；其他混用情況為 `HTTP_INPUT_API_MIXED`。將同一 DTO 型別宣告為多個參數時，應用程式會在啟動前以 `HTTP_INPUT_DTO_DUPLICATED` 拒絕；多個本文 DTO 對應 `HTTP_BODY_PARAMETERS_DUPLICATED`，不同 DTO 參數間同一來源的重複鍵對應 `HTTP_INPUT_KEY_DUPLICATED`。單一 Query、Header 或 Path DTO 內的輸入鍵重複時，錯誤為 `HTTP_INPUT_CONTRACT_INVALID`。允許在不同處理器中重複使用同一 DTO。

`input.Query[T]` 與結構體型別的 `input.Path[T]` 對無標籤公開欄位使用 lowerCamel 名稱。可用標籤覆寫名稱或以 `query:"-"` 排除欄位。相容的一般結構體指標方式和標頭 DTO 需要來源標籤。`param` 不是 `path` 的別名。

## 值與繫結行為的差異 {#binding}

| 輸入 | 原有讀取方式 | 新結構體輸入 |
| --- | --- | --- |
| 缺少的 page 與 size | Pagination 預設值為 `1`、`20` | 指標為 `nil`，範例處理器設定為 `1`、`20` |
| 無效數字 | `Values.Int` 與 Pagination 使用預設值 | HTTP 400，不替換為預設值 |
| 數字 `0` 或 bool `false` | 保留讀取方法的原有行為 | 區分值是否存在與 validator 對值的限制 |
| 重複查詢參數與逗號清單 | Values 讀取方法使用第一個值 | 切片同時處理重複鍵與逗號分隔 |

此範例的純量 ID 無法附加欄位驗證標籤；若需限制為正數，請在處理器中檢查。

`?tags=a,b&tags=c` 會變成 `["a","b","c"]`，`?tags=a,%20b` 會變成 `["a"," b"]`。不會任意移除空白、空元素或重複值。新的 bool 欄位使用 `strconv.ParseBool`，因此不會直接沿用原有讀取方式對 `yes`、`on` 等寫法的支援。

在 v0.7.1 中，原有 `query.Pagination` 也會在 `page` 或 `size` 重複時回傳 HTTP 400，例如 `?page=1&page=2`。這與 v0.6.5 讀取第一個值的行為不同。對於缺少值或單一值解析失敗的情況，仍使用原有預設值。

路徑區段不能省略。Path DTO 的指標欄位也不會使路徑變成選用；如果路由中沒有對應的 `path` 名稱，應用程式會在啟動時拒絕。

向一般值型別傳送明確的 JSON `null` 時，會以 HTTP 400 拒絕，而不會轉換為 `0`、`false` 或空字串。缺少欄位以及指標、map、slice 的 `null` 會分開處理，並由已註冊的 validator 最終判斷是否允許。自訂 `json.Unmarshaler` 自行決定如何處理 null。核心的 WebSocket 與消費者 JSON DTO 也適用相同的值型別規則。

HTTP v3 由核心解析本文，不會將路徑與 URL 查詢值合併至本文 DTO。表單也只讀取本文值。Spine DTO 輸入不呼叫 Echo Binder 與 JSONSerializer 擴充。請依 [HTTP v3 輸入與檔案生命週期](/zh-Hant/learn/migration/preview-features#body)移轉至標準解碼器。

`header:"Host"` 從 Go 請求的 `Request.Host` 讀取，並保留連接埠。不會改用 `X-Forwarded-Host`。標頭清單與查詢參數的語法不同，因此對於 Authorization、Cookie、Host 等，請使用字串或適當的自訂型別，不要宣告一般切片。

## 透過請求驗證 {#verify}

在應用程式執行時傳送以下請求。

```bash
curl -i -X POST 'http://localhost:8080/users/42?tags=a,b&tags=c' -H 'Content-Type: application/json' -H 'X-Request-ID: preview-check' --data '{"name":"Ada","count":0}'
curl -i -X POST 'http://localhost:8080/users/42?page=bad' -H 'Content-Type: application/json' -H 'X-Request-ID: preview-check' --data '{"name":"Ada","count":0}'
curl -i -X POST 'http://localhost:8080/users/42' -H 'Content-Type: application/json' -H 'X-Request-ID: preview-check' --data '{"name":"Ada","count":null}'
curl -i -X POST 'http://localhost:8080/users/42' -H 'Content-Type: application/json' --data '{"name":"Ada","count":0}'
curl -i http://localhost:8080/openapi.json
```

第一個請求回傳 HTTP 200，回應中的 `id` 為 `42`、`page` 為 `1`、`size` 為 `20`、`tags` 為 `["a","b","c"]`。無效 page、向一般 int 傳送 null、缺少必填標頭這三種情況分別回傳 HTTP 400。型別轉換失敗的 DTO 不會傳給對應的 validator 或處理器。參數依序解析，因此前面的 DTO 可能已經完成驗證。驗證錯誤中的 `fields[].in` 用來區分 `body`、`path`、`query`、`header` 來源。

最後一個請求回傳明確啟用的 OpenAPI JSON。規格產生器不會推斷處理器內部設定的 page 與 size 預設值。詳細設定與限制請參閱[執行階段 OpenAPI API](/zh-Hant/reference/api/openapi)。
