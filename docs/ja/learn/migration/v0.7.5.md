コントローラー、DI、インターセプター、検証の現在の推奨方式をまとめます。公開タグと CLI レシピを確認してからアプリ依存を固定します。

## コントローラーと DTO

```go
type UserPath struct {
	ID int64 `path:"id"`
}
type UserQuery struct {
	Name string `query:"name"`
}
type UserHeaders struct {
	RequestID string `header:"X-Request-ID"`
}
type CreateUser struct {
	Name string `json:"name" validate:"required"`
}

func (c *UserController) RegisterRoutes(r *api.Registry) {
	users := r.Group("/users", api.Interceptors((*Auth)(nil)))
	users.GET("/:id", c.Get)
	users.POST("/", c.Create)
}
func (c *UserController) Create(ctx spinectx.Ctx, body input.Body[CreateUser]) httpx.Response[CreateUser] {
	return httpx.Response[CreateUser]{Body: *body, Options: httpx.ResponseOptions{Status: 201}}
}
```

input.Path[UserPath]、input.Query[UserQuery]、input.Header[UserHeaders] を統一して使います。HTTP の通常 *DTO は拒否されます。Path/Query/Header は lowerCamel が既定でタグで変更します。Body は json/xml/form の規則です。成功応答は一つで、複数応答や不正な XML タグ、衝突は準備時に拒否します。

## 組み立てと自動検証

```go
engine, err := playground.New()
if err != nil {
	return nil, boot.Options{}, err
}
app := spine.New(echoplatform.Option(), spine.WithValidator(engine))
app.Constructor(
	constructor.Repository(&UserRepository{}),
	constructor.Service(&UserService{}),
	constructor.Controller(&UserController{}),
	constructor.Interceptor(&Auth{}),
)
```

必要な型と import を持つ BuildApplication に置きます。engine は playground.New のインスタンスです。タグの自動検証に DTO Validate メソッドは不要です。追加メソッドは自作し必要時に (*body).Validate() で呼びます。OpenAPI はその本体を推論しません。app.Validate はアプリ設定を検査します。生成子は単一戻り値で可変長引数を拒否します。

## コンテキストとインターセプター

ハンドラーと全フックは pkg/spine.Ctx を使い、標準 context.Context の直接注入も互換対応です。DB/イベントは ExecutionContext().Context()、実行値は Set/Get、HTTP/WS は公開ビューを使います。全体とルートの PreHandle はバインド前です。BeforeResponse エラーが応答に優先し、HTTPError は 400〜599 のみです。AfterCompletion は応答試行後でコミット場所ではありません。

[公開コンテキスト](/ja/reference/api/execution-context) / [適用範囲](/ja/learn/tutorial/4-interceptor) / [トランザクション](/ja/learn/tutorial/6-transaction)

## CLI と互換コード

現在の生成器は RegisterRoutes、役割生成子、入力ラッパーを出力する必要があります。生成後は contract check、verify、実 HTTP を確認します。app.Route、route.WithInterceptors、query.Values、header.Values、path、multipart.UploadedFiles は互換用の非推奨 API で、新規例や生成コードには使いません。過去の移行文書は当時の動作なので、現在の基準にはこのページを使います。
