# 0.7.5 API への移行

Spine `v0.7.5` に移行する際の HTTP 入力、コンテキスト、アプリの組み立て方を確認します。

## 正式版へのアップグレード {#stable-upgrade}

以下は Echo を使用する既存アプリの更新例です。他の HTTP 実装を使う場合は、[プラットフォームガイド](/ja/learn/getting-started/platforms)で互換バージョンを確認してください。HTTP v2 を使うアプリは、対応する HTTP v3 プラットフォームにも更新してください。

```sh
go install github.com/NARUBROWN/spine-cli/cmd/spine@v0.4.4
spine version
go get github.com/NARUBROWN/spine@v0.7.5 github.com/NARUBROWN/spine-echo-platform@v0.2.1
```

- [HTTP v3 の移行手順](https://github.com/NARUBROWN/spine/blob/v0.7.5/docs/migration/http-v3.md)

## コントローラーと DTO

```go
type UserPath struct {
	ID int64 `path:"id"`
}
type UserQuery struct {
	Name string `query:"name"`
}
type UserHeaders struct {
	RequestID string `header:"X-Request-ID"`
}
type CreateUser struct {
	Name string `json:"name" validate:"required"`
}

func (*UserController) RegisterRoutes(r *api.Registry) {
	users := r.Group("/users", api.Interceptors((*Auth)(nil)))
	users.GET("/:id", func(path input.Path[UserPath]) httpx.Response[map[string]int64] {
		return httpx.Response[map[string]int64]{Body: map[string]int64{"id": path.ID}}
	})
	users.POST("/", func(body input.Body[CreateUser]) httpx.Response[CreateUser] {
		return httpx.Response[CreateUser]{Body: *body, Options: httpx.ResponseOptions{Status: 201}}
	})
}
```

input.Path[UserPath]、input.Query[UserQuery]、input.Header[UserHeaders] を統一して使います。HTTP の通常 *DTO は拒否されます。Path/Query/Header は lowerCamel が既定でタグで変更します。Body は json/xml/form の規則です。成功応答は一つで、複数応答や不正な XML タグ、衝突は準備時に拒否します。

[コントローラーと DTO の規則](/ja/learn/tutorial/2-controller)

## 組み立てと自動検証

```go
engine, err := playground.New()
if err != nil {
	return nil, boot.Options{}, err
}
app := spine.New(echoplatform.Option(), spine.WithValidator(engine))
app.Constructor(
	constructor.Repository(&UserRepository{}),
	constructor.Service(&UserService{}),
	constructor.Controller(&UserController{}),
	constructor.Interceptor(&Auth{}),
)
```

必要な型と import を持つ BuildApplication に置きます。engine は playground.New のインスタンスです。タグの自動検証に DTO Validate メソッドは不要です。追加メソッドは自作し必要時に (*body).Validate() で呼びます。OpenAPI はその本体を推論しません。app.Validate はアプリ設定を検査します。生成子は単一戻り値で可変長引数を拒否します。

## コンテキストとインターセプター

HTTP ハンドラーはリクエストコンテキストが必要なときに pkg/spine.Ctx を宣言します。インターセプターの全フックは pkg/spine.Ctx を受け取ります。標準 context.Context の直接注入も互換対応です。DB/イベントは ExecutionContext().Context()、実行値は Set/Get、HTTP/WS は公開ビューを使います。全体とルートの PreHandle はバインド前です。BeforeResponse エラーが応答に優先し、HTTPError は 400〜599 のみです。AfterCompletion は応答試行後でコミット場所ではありません。

[公開コンテキスト](/ja/reference/api/execution-context) / [適用範囲](/ja/learn/tutorial/4-interceptor) / [トランザクション](/ja/learn/tutorial/6-transaction)

## CLI と互換コード

CLI `v0.4.4` は `RegisterRoutes`、役割別のコンストラクター、HTTP 入力ラッパーを生成します。移行後は `go mod tidy`、`spine contract check`、`spine verify` を実行し、実際の HTTP リクエストを確認してください。 app.Route、route.WithInterceptors、query.Values、header.Values、path、multipart.UploadedFiles は互換用の非推奨 API で、新規例や生成コードには使いません。過去の移行文書は当時の動作なので、現在の基準にはこのページを使います。

## 0.7.1 からの移行 {#from-v071}

Go モジュールで撤回された `v0.7.1` を使用している場合は、`v0.7.5` に更新してください。既存の HTTP ハンドラーの DTO ポインターは入力元に合ったラッパーで包み、HTTP プラットフォームも互換バージョンに更新します。
