# v0.7.1 のハンドラー入力への移行

Spine `v0.7.1` ではパス、クエリ、ヘッダーを入力元別の構造体で受け取り、フィールドに直接アクセスできます。このガイドでは移行手順とバインディングの違いを説明します。`query.Values`、`header.Values`、`query.Pagination` と従来の `path` ラッパーは非推奨として維持され、同じハンドラーで新しい Path、Query、Header 入力と混在できません。

## 対象バージョン {#versions}

以下の独立例は正式版コア `v0.7.1`、Echo `v0.2.0`、playground `v0.2.0` を使います。コアと Echo は Go 1.25.5 以上、playground は Go 1.26 以上が必要です。Go モジュールを作成し、依存関係をインストールして `go.mod` と `go.sum` を保存してください。

```bash
go get github.com/NARUBROWN/spine@v0.7.1 github.com/NARUBROWN/spine-echo-platform@v0.2.0 github.com/NARUBROWN/spine-validator-playground@v0.2.0
```

validator がない場合も型変換は実行されますが、`validate` タグは検査されず、OpenAPI はパス中心の情報を提供します。UI が必要なら [OpenAPI UI 設定](/ja/reference/api/openapi#tools)を別途有効にしてください。

## 既存の引数と新しい DTO の対応 {#mapping}

| 既存の入力 | 新しい入力 | ハンドラー内での読み取り方 |
| --- | --- | --- |
| `id path.Int` と `id.Value` | `path:"user_id"` フィールドを持つ `*UserPath` | `p.UserID` |
| `path.String`、`path.Boolean` | 名前と値の型を宣言した Path DTO のフィールド | 通常のフィールドアクセス |
| `q query.Values` | `query` タグを持つ `*UserQuery` | `q.Page`、`q.Tags` |
| `page query.Pagination` | Query DTO の `Page`、`Size` フィールド | 省略時はアプリで既定値を適用 |
| `headers header.Values` | `header` タグを持つ `*UserHeaders` | `headers.RequestID` |
| 既存の本文 DTO | 本文用の構造体へのポインターを別に維持 | `body.Name` |

パス、クエリ、ヘッダーの入力フィールドを 1 つの構造体に混在させないでください。`path` タグは、大文字と小文字も含めてルート変数名と完全に一致させます。引数名や構造体のフィールド順ではパスを割り当てません。

## 新しい入力を使用するハンドラーの完全な例 {#example}

以下は、入力の宣言と動作を確認できる独立した参考アプリの `main.go` です。既存アプリでは、DTO、ハンドラー、起動設定を現在の composition に反映してください。

```go
package main

import (
    "log"

    "github.com/NARUBROWN/spine"
    echoplatform "github.com/NARUBROWN/spine-echo-platform"
    playground "github.com/NARUBROWN/spine-validator-playground"
    "github.com/NARUBROWN/spine/pkg/api"
    "github.com/NARUBROWN/spine/pkg/boot"
    "github.com/NARUBROWN/spine/pkg/constructor"
    "github.com/NARUBROWN/spine/pkg/httpx"
)

type UserPath struct {
    UserID int64 `path:"user_id" validate:"gt=0"`
}

type UserQuery struct {
    Page *int     `query:"page"`
    Size *int     `query:"size"`
    Tags []string `query:"tags"`
}

type UserHeaders struct {
    RequestID string `header:"X-Request-ID" validate:"required"`
    Host      string `header:"Host"`
}

type UpdateBody struct {
    Name  string `json:"name" validate:"required"`
    Count int    `json:"count" validate:"gte=0"`
}

type UserView struct {
    ID        int64    `json:"id"`
    Name      string   `json:"name"`
    Count     int      `json:"count"`
    Page      int      `json:"page"`
    Size      int      `json:"size"`
    Tags      []string `json:"tags"`
    RequestID string   `json:"request_id"`
    Host      string   `json:"host"`
}

type UserController struct{}

func (*UserController) Constructor() *UserController { return &UserController{} }

func (c *UserController) RegisterRoutes(r *api.Registry) {
    r.POST("/users/:user_id", func(body *UpdateBody, p *UserPath, q *UserQuery, headers *UserHeaders) httpx.Response[UserView] {
        return c.Update(body, p, q, headers)
    })
}

func (*UserController) Update(body *UpdateBody, p *UserPath, q *UserQuery, headers *UserHeaders) httpx.Response[UserView] {
    page, size := 1, 20
    if q.Page != nil {
        page = *q.Page
    }
    if q.Size != nil {
        size = *q.Size
    }
    return httpx.Response[UserView]{Body: UserView{
        ID: p.UserID, Name: body.Name, Count: body.Count,
        Page: page, Size: size, Tags: q.Tags,
        RequestID: headers.RequestID, Host: headers.Host,
    }}
}

func main() {
    engine, err := playground.New()
    if err != nil {
        log.Fatal(err)
    }
    app := spine.New(echoplatform.Option(), spine.WithValidator(engine))
    app.Constructor(constructor.Controller(&UserController{}))
    options := boot.Options{
        Address: ":8080",
        EnableGracefulShutdown: true,
        HTTP: &boot.HTTPOptions{
            OpenAPI: boot.OpenAPIOptions{Enabled: true},
        },
    }
    if err := app.Run(options); err != nil {
        log.Fatal(err)
    }
}
```

入力が必須かどうかは、登録した validator の契約に従います。上の例の `Name` と `RequestID` は `validate:"required"` によって必須になり、ポインターかどうかだけでは必須かどうかを決めません。`Page` と `Size` のポインターは、省略と実際の数値 `0` を区別します。正の数や最大サイズなどの制約は、アプリ側で validator のルールとして別途宣言する必要があります。

依存関係のバージョンを固定してコードを反映したら、プロジェクトのルートで実行します。参考アプリはそのファイルを単独で実行でき、既存アプリでは現在のエントリーポイントを使用します。

```bash
go mod tidy
go run main.go
```

## ハンドラーごとに入力をまとめて移行する {#compatibility}

| 組み合わせ | v0.7.1 での処理 |
| --- | --- |
| 既存の入力 API のみを使用 | Deprecated のシグネチャを維持。Pagination の page/size の重複は HTTP 400 |
| 既存の入力と既存の本文 DTO または context | 引き続きサポート |
| 新しい Path、Query、Header DTO と本文 DTO または context | サポート |
| Deprecated の入力と新しい Path、Query、Header DTO を 1 つのハンドラーで混在 | 入力元が異なる場合も起動を拒否 |
| 別々のハンドラーで既存 API と新しい DTO をそれぞれ使用 | サポート |

たとえば、パスだけを `*UserPath` に変更して、同じハンドラーに `query.Values` や `query.Pagination` を残すことはできません。そのハンドラーの Deprecated 入力引数をすべてまとめて移行してください。`context.Context` とコントローラーコンテキストは Deprecated 入力ではなく、そのまま注入できます。

新しい Path DTO と既存の path ラッパーを混在させると `HTTP_PATH_INPUT_MIXED`、それ以外の混在は `HTTP_INPUT_API_MIXED` になります。同じ DTO 型を引数に重複して宣言すると `HTTP_INPUT_DTO_DUPLICATED`、複数の本文 DTO は `HTTP_BODY_PARAMETERS_DUPLICATED`、異なる DTO 引数間で同じ入力元のキーが重複すると `HTTP_INPUT_KEY_DUPLICATED` で起動前に拒否されます。1 つの Query、Header、Path DTO 内の入力キーの重複は `HTTP_INPUT_CONTRACT_INVALID` になります。同じ DTO を別のハンドラーで再利用することはできます。

Query、Header、Path DTO の公開フィールドには、該当する入力元のタグを指定するか、`query:"-"` のように明示的に除外します。`param` は `path` の別名ではありません。Query DTO と Header DTO にシリアライズ名として `json` タグを併記することはできますが、入力元が本文に変わるわけではありません。

## 値とバインディングの動作の違い {#binding}

| 入力 | 従来の読み取り方式 | 新しい構造体入力 |
| --- | --- | --- |
| page と size の省略 | Pagination の既定値は `1`、`20` | ポインターは `nil`、例のハンドラーが `1`、`20` を適用 |
| 不正な数値 | `Values.Int` と Pagination は既定値を使用 | HTTP 400、既定値に置き換えない |
| 数値 `0` または bool `false` | 従来の読み取りメソッドの動作を維持 | 値の有無と validator による値の制約を区別 |
| クエリの繰り返しとカンマ区切りのリスト | Values の読み取りメソッドは最初の値を使用 | スライスはキーの繰り返しとカンマ区切りの両方を処理 |

`?tags=a,b&tags=c` は `["a","b","c"]`、`?tags=a,%20b` は `["a"," b"]` になります。空白、空要素、重複は自動的に削除されません。新しい bool フィールドは `strconv.ParseBool` を使用するため、従来の読み取りで受け付けていた `yes`、`on` などの表記はそのまま使用できません。

v0.7.1 では既存の `query.Pagination` も、`?page=1&page=2` のように `page` または `size` が重複すると HTTP 400 を返します。最初の値を読み取っていた v0.6.5 とは異なります。値の欠落と、重複していない値の解析失敗には従来の既定値を使用します。

パスのセグメントは省略できません。Path DTO のポインターフィールドもパスを省略可能にはせず、`path` の名前がルートに存在しない場合は起動時に拒否されます。

通常の値型に明示的な JSON `null` を送ると、`0`、`false`、空文字列には変換せず、HTTP 400 で拒否します。省略されたフィールドと、ポインター、map、slice の `null` は別に扱い、最終的に許可するかどうかは登録した validator が判断します。カスタムの `json.Unmarshaler` は独自の null 処理を定義します。コアの WebSocket とコンシューマーの JSON DTO にも同じ値型のルールが適用されます。

HTTP v3 ではコアが本文を解析し、パスや URL クエリを本文 DTO にマージしません。フォームも本文の値だけを読みます。Spine DTO 入力では Echo Binder と JSONSerializer 拡張を呼びません。[HTTP v3 の入力とファイルの有効期間](/ja/learn/migration/preview-features#body)に従い標準デコーダーに移行してください。

`header:"Host"` は Go リクエストの `Request.Host` から読み取り、ポートも維持します。代わりに `X-Forwarded-Host` を使用することはありません。ヘッダーのリストはクエリと構文が異なるため、Authorization、Cookie、Host などには通常のスライスを宣言せず、文字列や適切なユーザー定義型を使用してください。

## リクエストで確認する {#verify}

アプリを起動した状態で、次のリクエストを送信します。

```bash
curl -i -X POST 'http://localhost:8080/users/42?tags=a,b&tags=c' -H 'Content-Type: application/json' -H 'X-Request-ID: preview-check' --data '{"name":"Ada","count":0}'
curl -i -X POST 'http://localhost:8080/users/42?page=bad' -H 'Content-Type: application/json' -H 'X-Request-ID: preview-check' --data '{"name":"Ada","count":0}'
curl -i -X POST 'http://localhost:8080/users/42' -H 'Content-Type: application/json' -H 'X-Request-ID: preview-check' --data '{"name":"Ada","count":null}'
curl -i -X POST 'http://localhost:8080/users/42' -H 'Content-Type: application/json' --data '{"name":"Ada","count":0}'
curl -i http://localhost:8080/openapi.json
```

最初のリクエストは HTTP 200 を返し、応答の `id` は `42`、`page` は `1`、`size` は `20`、`tags` は `["a","b","c"]` になります。不正な page、通常の int に送った null、必須ヘッダーの欠落は、それぞれ HTTP 400 になります。形式変換に失敗した DTO は、その DTO の validator とハンドラーに渡しません。引数は順番に解釈するため、それより前の DTO の検証はすでに実行されている場合があります。検証エラーの `fields[].in` は、`body`、`path`、`query`、`header` の入力元を区別します。

最後のリクエストは、明示的に有効化した OpenAPI JSON を返します。ドキュメントの生成処理は、ハンドラー内で適用した page と size の既定値を推論しません。詳細な設定と制限は[ランタイム OpenAPI API](/ja/reference/api/openapi)を参照してください。
