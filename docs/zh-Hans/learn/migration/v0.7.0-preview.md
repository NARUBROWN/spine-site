# v0.7.0 Preview 处理器输入迁移

从 Spine `v0.7.0-preview.1` 起，可以分别使用结构体指针接收路径、查询和请求头输入，并直接访问字段。本指南说明如何将现有应用的输入参数迁移到这种方式。

::: warning Preview 版本与兼容性
本页介绍的 Preview API 无法直接用于正式版 `v0.6.5`。从 `v0.7.0-preview.1` 起，`query.Values`、`header.Values`、`query.Pagination` 以及 `path.Int`、`path.String`、`path.Boolean` 均已标记为 Deprecated。过渡期间仍保留原有方式，但不能在同一处理器中与新的 Path、Query、Header DTO 混用。移除版本尚未确定。
:::

## 适用版本 {#versions}

| 模块 | 版本查询 | 作用 |
| --- | --- | --- |
| `github.com/NARUBROWN/spine` | `@preview` | 输入 DTO 契约与运行时 OpenAPI |
| `github.com/NARUBROWN/spine-echo-platform` | `@preview` | HTTP 正文绑定、Host 与 JSON null 处理 |
| `github.com/NARUBROWN/spine-validator-playground` | `@preview` | 可选验证与详细规范描述 |

核心与 Echo 需要 Go 1.25.5 或更高版本；下方使用 playground 的示例需要 Go 1.26 或更高版本。如果还使用 WebSocket 或事件平台，请为相应平台选择 `@preview`。

通过 `@preview` 安装 Preview CLI 的最新分支。使用 `spine version` 查看实际版本，其中可能包含已发布标签之间的变更。

```bash
go install github.com/NARUBROWN/spine-cli/cmd/spine@preview
spine version
```

该 CLI 的 `new` 默认使用 `platform-contracts-preview`，解析核心与所选平台的 Preview 分支，并将实际版本记录在 `go.mod` 中。创建项目请参照[第一个应用](/zh-Hans/learn/getting-started/first-app)。若按下方示例使用 playground，请为 `new` 添加 `--validator playground`。

仅安装 CLI 不会更改现有应用的配方。在 `spine.toml` 中保留模块路径、入口点、composition、端口、布局与平台选择，仅将 `recipe` 改为下方的值。检查 `spine update --dry-run` 的变更，再执行输出中显示的应用命令。该命令不会改写应用源码，DTO 和启动选项需要按下文自行修改。

```toml
recipe = "platform-contracts-preview"
```

构建独立参考应用或直接对齐依赖时，请在 `go.mod` 所在目录中指定以下版本。

```bash
go get github.com/NARUBROWN/spine@preview github.com/NARUBROWN/spine-echo-platform@preview github.com/NARUBROWN/spine-validator-playground@preview
```

下方示例使用 playground。不使用验证器的应用可以保留现有的验证器配置。新 DTO 的类型转换不依赖验证器，但未配置验证器时不会检查 `validate` 标签，OpenAPI 也只提供以路径为主的信息。

::: tip 文档 UI 从 Preview 2 起提供
输入 DTO 与 JSON 规范从 `v0.7.0-preview.1` 起可用，通过 `boot.OpenAPIOptions.UI` 注册 Swagger UI 和 ReDoc 从 `v0.7.0-preview.2` 起可用。UI 不会自动启用，请添加[内嵌 UI 注册与启动选项](/zh-Hans/reference/api/openapi#tools)。
:::

## 原有参数与新 DTO 的对应关系 {#mapping}

| 原有输入 | 新输入 | 在处理器中读取的方式 |
| --- | --- | --- |
| `id path.Int` 与 `id.Value` | 包含 `path:"user_id"` 字段的 `*UserPath` | `p.UserID` |
| `path.String`、`path.Boolean` | 声明名称与值类型的 Path DTO 字段 | 直接访问字段 |
| `q query.Values` | 带有 `query` 标签的 `*UserQuery` | `q.Page`、`q.Tags` |
| `page query.Pagination` | Query DTO 的 `Page`、`Size` 字段 | 缺失时由应用设置默认值 |
| `headers header.Values` | 带有 `header` 标签的 `*UserHeaders` | `headers.RequestID` |
| 原有正文 DTO | 保留独立的正文结构体指针 | `body.Name` |

不要在同一个结构体中混合路径、查询与请求头的输入字段。`path` 标签必须与路由变量名称完全一致，包括大小写。路径不会按照参数名称或结构体字段顺序分配。

## 新处理器的完整示例 {#example}

以下是独立参考应用的 `main.go`，可用于同时检查输入声明与行为。对于现有应用，请将 DTO、处理器与启动配置整合到当前的 composition 中。继续使用原有的 `app.Route` 与构造函数注册 API。

```go
package main

import (
    "log"

    "github.com/NARUBROWN/spine"
    echoplatform "github.com/NARUBROWN/spine-echo-platform"
    playground "github.com/NARUBROWN/spine-validator-playground"
    "github.com/NARUBROWN/spine/pkg/boot"
    "github.com/NARUBROWN/spine/pkg/httpx"
)

type UserPath struct {
    UserID int64 `path:"user_id" validate:"gt=0"`
}

type UserQuery struct {
    Page *int     `query:"page"`
    Size *int     `query:"size"`
    Tags []string `query:"tags"`
}

type UserHeaders struct {
    RequestID string `header:"X-Request-ID" validate:"required"`
    Host      string `header:"Host"`
}

type UpdateBody struct {
    Name  string `json:"name" validate:"required"`
    Count int    `json:"count" validate:"gte=0"`
}

type UserView struct {
    ID        int64    `json:"id"`
    Name      string   `json:"name"`
    Count     int      `json:"count"`
    Page      int      `json:"page"`
    Size      int      `json:"size"`
    Tags      []string `json:"tags"`
    RequestID string   `json:"request_id"`
    Host      string   `json:"host"`
}

type UserController struct{}

func (*UserController) Update(body *UpdateBody, p *UserPath, q *UserQuery, headers *UserHeaders) httpx.Response[UserView] {
    page, size := 1, 20
    if q.Page != nil {
        page = *q.Page
    }
    if q.Size != nil {
        size = *q.Size
    }
    return httpx.Response[UserView]{Body: UserView{
        ID: p.UserID, Name: body.Name, Count: body.Count,
        Page: page, Size: size, Tags: q.Tags,
        RequestID: headers.RequestID, Host: headers.Host,
    }}
}

func main() {
    engine, err := playground.New()
    if err != nil {
        log.Fatal(err)
    }
    app := spine.New(echoplatform.Option(), spine.WithValidator(engine))
    app.Constructor(func() *UserController { return &UserController{} })
    app.Route("POST", "/users/:user_id", (*UserController).Update)
    options := boot.Options{
        Address: ":8080",
        EnableGracefulShutdown: true,
        HTTP: &boot.HTTPOptions{
            OpenAPI: boot.OpenAPIOptions{Enabled: true},
        },
    }
    if err := app.Run(options); err != nil {
        log.Fatal(err)
    }
}
```

输入是否必填由已注册 validator 的契约决定。上例中的 `Name` 与 `RequestID` 通过 `validate:"required"` 声明为必填，不会仅根据是否为指针决定。`Page` 与 `Size` 使用指针来区分缺失值和实际数字 `0`。正数、最大值等规则需要由应用另外向 validator 声明。

固定依赖版本并应用代码后，在项目根目录运行。参考应用可以单独运行该文件；现有应用则使用当前入口点。

```bash
go mod tidy
go run main.go
```

## 逐个处理器完整迁移 {#compatibility}

| 组合 | Preview 中的处理方式 |
| --- | --- |
| 仅使用原有输入 API | 保留 Deprecated 签名，Pagination 的 page/size 重复时返回 HTTP 400 |
| 原有输入与原有正文 DTO 或 context | 继续支持 |
| 新 Path、Query、Header DTO 与正文 DTO 或 context | 支持 |
| 在同一处理器中混用 Deprecated 输入与新 Path、Query、Header DTO | 即使来源不同，也拒绝启动 |
| 在不同处理器中分别使用原有 API 与新 DTO | 支持 |

例如，不能只将路径改为 `*UserPath`，却在同一处理器中保留 `query.Values` 或 `query.Pagination`。请一起迁移该处理器的所有 Deprecated 输入参数。`context.Context` 与控制器上下文不属于 Deprecated 输入，可以继续注入。

混用新 Path DTO 与原有 path 包装类型时，错误为 `HTTP_PATH_INPUT_MIXED`；其他混用情况为 `HTTP_INPUT_API_MIXED`。将同一 DTO 类型声明为多个参数时，应用会在启动前以 `HTTP_INPUT_DTO_DUPLICATED` 拒绝；多个正文 DTO 对应 `HTTP_BODY_PARAMETERS_DUPLICATED`，不同 DTO 参数间同一来源的重复键对应 `HTTP_INPUT_KEY_DUPLICATED`。单个 Query、Header 或 Path DTO 内的输入键重复时，错误为 `HTTP_INPUT_CONTRACT_INVALID`。允许在不同处理器中复用同一 DTO。

Query、Header、Path DTO 的公开字段必须指定对应来源的标签，或像 `query:"-"` 一样显式排除。`param` 不是 `path` 的别名。Query 或 Header DTO 可以同时使用 `json` 标签指定序列化名称，但这不会将输入来源改为正文。

## 值与绑定行为的差异 {#binding}

| 输入 | 原有读取方式 | 新结构体输入 |
| --- | --- | --- |
| 缺失的 page 与 size | Pagination 默认值为 `1`、`20` | 指针为 `nil`，示例处理器设置为 `1`、`20` |
| 无效数字 | `Values.Int` 与 Pagination 使用默认值 | HTTP 400，不替换为默认值 |
| 数字 `0` 或 bool `false` | 保留读取方法的原有行为 | 区分值是否存在与 validator 对值的约束 |
| 重复查询参数与逗号列表 | Values 读取方法使用第一个值 | 切片同时处理重复键与逗号分隔 |

`?tags=a,b&tags=c` 会变为 `["a","b","c"]`，`?tags=a,%20b` 会变为 `["a"," b"]`。不会擅自移除空白、空元素或重复值。新的 bool 字段使用 `strconv.ParseBool`，因此不会直接沿用原有读取方式对 `yes`、`on` 等写法的支持。

在 Preview 中，原有 `query.Pagination` 也会在 `page` 或 `size` 重复时返回 HTTP 400，例如 `?page=1&page=2`。这与稳定版读取第一个值的行为不同。对于缺少值或单个值解析失败的情况，仍使用原有默认值。

路径段不能省略。Path DTO 的指针字段也不会使路径变为可选；如果路由中没有对应的 `path` 名称，应用会在启动时拒绝。

向普通值类型发送显式 JSON `null` 时，会以 HTTP 400 拒绝，而不会转换为 `0`、`false` 或空字符串。缺失字段以及指针、map、slice 的 `null` 会单独处理，并由已注册的 validator 最终判断是否允许。自定义 `json.Unmarshaler` 自行决定如何处理 null。核心的 WebSocket 与消费者 JSON DTO 也适用相同的值类型规则。

Echo Preview 的默认正文绑定不会将路径与 URL 查询参数合并到正文 DTO。表单也只读取正文值。如果现有应用依赖这种合并行为，请按来源拆分 DTO。自定义 Binder 则遵循其自身实现的契约。

`header:"Host"` 从 Go 请求的 `Request.Host` 读取，并保留端口。不会改用 `X-Forwarded-Host`。请求头列表与查询参数的语法不同，因此对于 Authorization、Cookie、Host 等，请使用字符串或适当的自定义类型，不要声明普通切片。

## 通过请求验证 {#verify}

在应用运行时发送以下请求。

```bash
curl -i -X POST 'http://localhost:8080/users/42?tags=a,b&tags=c' -H 'Content-Type: application/json' -H 'X-Request-ID: preview-check' --data '{"name":"Ada","count":0}'
curl -i -X POST 'http://localhost:8080/users/42?page=bad' -H 'Content-Type: application/json' -H 'X-Request-ID: preview-check' --data '{"name":"Ada","count":0}'
curl -i -X POST 'http://localhost:8080/users/42' -H 'Content-Type: application/json' -H 'X-Request-ID: preview-check' --data '{"name":"Ada","count":null}'
curl -i -X POST 'http://localhost:8080/users/42' -H 'Content-Type: application/json' --data '{"name":"Ada","count":0}'
curl -i http://localhost:8080/openapi.json
```

第一个请求返回 HTTP 200，响应中的 `id` 为 `42`、`page` 为 `1`、`size` 为 `20`、`tags` 为 `["a","b","c"]`。无效 page、向普通 int 发送 null、缺少必填请求头这三种情况分别返回 HTTP 400。类型转换失败的 DTO 不会传递给对应的 validator 或处理器。参数按顺序解析，因此前面的 DTO 可能已经完成验证。验证错误中的 `fields[].in` 用于区分 `body`、`path`、`query`、`header` 来源。

最后一个请求返回显式启用的 OpenAPI JSON。规范生成器不会推断处理器内部设置的 page 与 size 默认值。详细配置与限制请参阅[运行时 OpenAPI API](/zh-Hans/reference/api/openapi)。
