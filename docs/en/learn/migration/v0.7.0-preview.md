# Migrate handler inputs to v0.7.0 Preview

Starting with Spine `v0.7.0-preview.1`, you can receive path, query, and header inputs as separate struct pointers and access their fields directly. This guide explains how to migrate input parameters in an existing app.

::: warning Preview versions and compatibility
This page describes Preview APIs that cannot be applied directly to stable `v0.6.5`. `query.Values`, `header.Values`, `query.Pagination`, `path.Int`, `path.String`, and `path.Boolean` are Deprecated starting with `v0.7.0-preview.1`. The existing APIs remain available during migration, but you cannot mix them with new Path, Query, or Header DTOs in one handler. No removal version has been set.
:::

Select Swagger UI and ReDoc through `boot.HTTPOptions.OpenAPI.UI`. See [Preview features and boot options](/en/learn/migration/preview-features#boot) for a runnable example, TLS, and HTTP v3 changes.

## Applicable versions {#versions}

| Module | Version query | Role |
| --- | --- | --- |
| `github.com/NARUBROWN/spine` | `@preview` | Input DTO contracts and runtime OpenAPI |
| `github.com/NARUBROWN/spine-echo-platform` | `@preview` | Raw HTTP I/O and managed server |
| `github.com/NARUBROWN/spine-validator-playground` | `@preview` | Optional validation and detailed schema descriptions |

Core and Echo require Go 1.25.5 or later. The example below uses playground and requires Go 1.26 or later. If you also use WebSocket or event platforms, select `@preview` for those platforms.

Install the latest Preview CLI branch with `@preview`. Check the installed version with `spine version`; it may include changes between published tags.

```bash
go install github.com/NARUBROWN/spine-cli/cmd/spine@preview
spine version
```

This CLI’s `new` command defaults to `platform-contracts-preview`, resolving the Preview branches for core and selected platforms and recording the actual versions in `go.mod`. Follow [First App](/en/learn/getting-started/first-app) to create a project. Add `--validator playground` to `new` when using playground as in the example below.

Installing the CLI does not change an existing app’s recipe. In `spine.toml`, preserve the module path, entrypoint, composition, port, layout, and platform selections, and change only `recipe` to the value below. Review the changes from `spine update --dry-run`, then run the apply command shown in its output. This command does not rewrite application source; apply the DTO and boot option changes below yourself.

```toml
recipe = "platform-contracts-preview"
```

To build the standalone reference app or align dependencies directly, pin the following versions in the directory containing `go.mod`.

```bash
go get github.com/NARUBROWN/spine@preview github.com/NARUBROWN/spine-echo-platform@preview github.com/NARUBROWN/spine-validator-playground@preview
```

The example below uses playground. Apps that do not use a validator can keep their existing validator configuration. Type conversion for new DTOs works without a validator, but `validate` tags are not checked and OpenAPI provides only route-oriented information.

::: tip Documentation UIs require Preview 2
Input DTOs and JSON documents are available from `v0.7.0-preview.1`; Swagger UI and ReDoc registration through `boot.OpenAPIOptions.UI` is available from `v0.7.0-preview.2`. UIs are not enabled automatically; apply the [embedded UI registration and boot options](/en/reference/api/openapi#tools).
:::

## Map existing parameters to new DTOs {#mapping}

| Existing input | New input | Access inside the handler |
| --- | --- | --- |
| `id path.Int` and `id.Value` | `*UserPath` with a `path:"user_id"` field | `p.UserID` |
| `path.String`, `path.Boolean` | Path DTO fields with explicit names and value types | Direct field access |
| `q query.Values` | `*UserQuery` with `query` tags | `q.Page`, `q.Tags` |
| `page query.Pagination` | `Page` and `Size` fields in a Query DTO | Apply defaults in the app when omitted |
| `headers header.Values` | `*UserHeaders` with `header` tags | `headers.RequestID` |
| Existing body DTO | Keep a separate pointer to a body struct | `body.Name` |

Do not mix path, query, and header input fields in one struct. A `path` tag must match the route variable name exactly, including case. Parameter names and struct field order do not determine path assignments.

## Complete example with the new inputs {#example}

The following `main.go` is a standalone reference app for checking input declarations and behavior together. In an existing app, incorporate the DTOs, handler, and boot configuration into your current composition. Continue using the same `app.Route` and constructor registration APIs.

```go
package main

import (
    "log"

    "github.com/NARUBROWN/spine"
    echoplatform "github.com/NARUBROWN/spine-echo-platform"
    playground "github.com/NARUBROWN/spine-validator-playground"
    "github.com/NARUBROWN/spine/pkg/boot"
    "github.com/NARUBROWN/spine/pkg/httpx"
)

type UserPath struct {
    UserID int64 `path:"user_id" validate:"gt=0"`
}

type UserQuery struct {
    Page *int     `query:"page"`
    Size *int     `query:"size"`
    Tags []string `query:"tags"`
}

type UserHeaders struct {
    RequestID string `header:"X-Request-ID" validate:"required"`
    Host      string `header:"Host"`
}

type UpdateBody struct {
    Name  string `json:"name" validate:"required"`
    Count int    `json:"count" validate:"gte=0"`
}

type UserView struct {
    ID        int64    `json:"id"`
    Name      string   `json:"name"`
    Count     int      `json:"count"`
    Page      int      `json:"page"`
    Size      int      `json:"size"`
    Tags      []string `json:"tags"`
    RequestID string   `json:"request_id"`
    Host      string   `json:"host"`
}

type UserController struct{}

func (*UserController) Update(body *UpdateBody, p *UserPath, q *UserQuery, headers *UserHeaders) httpx.Response[UserView] {
    page, size := 1, 20
    if q.Page != nil {
        page = *q.Page
    }
    if q.Size != nil {
        size = *q.Size
    }
    return httpx.Response[UserView]{Body: UserView{
        ID: p.UserID, Name: body.Name, Count: body.Count,
        Page: page, Size: size, Tags: q.Tags,
        RequestID: headers.RequestID, Host: headers.Host,
    }}
}

func main() {
    engine, err := playground.New()
    if err != nil {
        log.Fatal(err)
    }
    app := spine.New(echoplatform.Option(), spine.WithValidator(engine))
    app.Constructor(func() *UserController { return &UserController{} })
    app.Route("POST", "/users/:user_id", (*UserController).Update)
    options := boot.Options{
        Address: ":8080",
        EnableGracefulShutdown: true,
        HTTP: &boot.HTTPOptions{
            OpenAPI: boot.OpenAPIOptions{Enabled: true},
        },
    }
    if err := app.Run(options); err != nil {
        log.Fatal(err)
    }
}
```

Required inputs follow the registered validator's contract. In the example above, `Name` and `RequestID` are required because they have `validate:"required"`; pointer status alone does not determine whether a field is required. Pointers for `Page` and `Size` distinguish an omitted value from an actual numeric `0`. The app must declare additional validator rules for constraints such as positive values or maximum sizes.

After pinning dependencies and applying the code, run the app from the project root. You can run the reference app as a standalone file; existing apps should use their current entrypoint.

```bash
go mod tidy
go run main.go
```

## Migrate all inputs in one handler together {#compatibility}

| Combination | Preview behavior |
| --- | --- |
| Existing input APIs only | Deprecated signatures remain supported; repeated Pagination page/size returns HTTP 400 |
| Existing inputs with an existing body DTO or context | Still supported |
| New Path, Query, or Header DTOs with a body DTO or context | Supported |
| Deprecated inputs mixed with new Path, Query, or Header DTOs in one handler | Rejected at startup even when the input sources differ |
| Existing APIs in one handler and new DTOs in another | Supported |

For example, you cannot change only the path input to `*UserPath` and leave `query.Values` or `query.Pagination` in the same handler. Migrate all Deprecated input parameters in that handler together. `context.Context` and controller contexts are not Deprecated inputs and can still be injected.

Mixing new Path DTOs with existing path wrappers produces `HTTP_PATH_INPUT_MIXED`; other mixtures produce `HTTP_INPUT_API_MIXED`. Duplicate parameters with the same DTO type are rejected before startup with `HTTP_INPUT_DTO_DUPLICATED`, multiple body DTOs with `HTTP_BODY_PARAMETERS_DUPLICATED`, and duplicate keys from the same source across different DTO parameters with `HTTP_INPUT_KEY_DUPLICATED`. Duplicate input keys within one Query, Header, or Path DTO produce `HTTP_INPUT_CONTRACT_INVALID`. You can reuse the same DTO in different handlers.

Public fields in Query, Header, and Path DTOs must have the corresponding source tag or be explicitly excluded with a tag such as `query:"-"`. `param` is not an alias for `path`. Query and Header DTOs can also have `json` tags for serialization names, but those tags do not change their input source to the body.

## Differences in values and binding {#binding}

| Input | Existing lookup behavior | New struct input |
| --- | --- | --- |
| Omitted page and size | Pagination defaults to `1` and `20` | Pointers are `nil`; the example handler applies `1` and `20` |
| Invalid number | `Values.Int` and Pagination use defaults | HTTP 400, with no fallback to defaults |
| Numeric `0` or bool `false` | Existing lookup method behavior is preserved | Value presence and validator value constraints are separate |
| Repeated query keys and comma-separated lists | Values lookup methods use the first value | Slices handle both repeated keys and comma-separated values |

`?tags=a,b&tags=c` becomes `["a","b","c"]`, and `?tags=a,%20b` becomes `["a"," b"]`. Whitespace, empty elements, and duplicates are not removed automatically. New bool fields use `strconv.ParseBool`, so they do not accept all forms supported by the existing lookup methods, such as `yes` and `on`.

In Preview, existing `query.Pagination` also returns HTTP 400 when `page` or `size` is repeated, as in `?page=1&page=2`. This differs from the stable version, which read the first value. Missing values and parse failures for a single value retain the existing defaults.

Path segments cannot be omitted. A pointer field in a Path DTO does not make the path optional. A `path` name that is absent from the route is rejected at startup.

Explicit JSON `null` for an ordinary value type is rejected with HTTP 400 instead of being converted to `0`, `false`, or an empty string. Omitted fields and `null` for pointers, maps, and slices are handled separately, and the registered validator determines whether they are ultimately allowed. A custom `json.Unmarshaler` defines its own null handling. The same value-type rule applies to the core's WebSocket and consumer JSON DTOs.

In HTTP v3, core parses bodies without merging path or URL query values into body DTOs. Forms read only body values. Echo Binder and JSONSerializer extensions are not called for Spine DTO input. Migrate to standard decoders as described in [HTTP v3 inputs and file lifetime](/en/learn/migration/preview-features#body).

`header:"Host"` reads Go's `Request.Host`, preserving the port. It does not substitute `X-Forwarded-Host`. Header lists use different syntax from queries. For headers such as Authorization, Cookie, and Host, use strings or appropriate custom types rather than ordinary slices.

## Verify with requests {#verify}

Send the following requests while the app is running.

```bash
curl -i -X POST 'http://localhost:8080/users/42?tags=a,b&tags=c' -H 'Content-Type: application/json' -H 'X-Request-ID: preview-check' --data '{"name":"Ada","count":0}'
curl -i -X POST 'http://localhost:8080/users/42?page=bad' -H 'Content-Type: application/json' -H 'X-Request-ID: preview-check' --data '{"name":"Ada","count":0}'
curl -i -X POST 'http://localhost:8080/users/42' -H 'Content-Type: application/json' -H 'X-Request-ID: preview-check' --data '{"name":"Ada","count":null}'
curl -i -X POST 'http://localhost:8080/users/42' -H 'Content-Type: application/json' --data '{"name":"Ada","count":0}'
curl -i http://localhost:8080/openapi.json
```

The first request returns HTTP 200 with `id` set to `42`, `page` to `1`, `size` to `20`, and `tags` to `["a","b","c"]`. An invalid page, null sent to an ordinary int, and a missing required header each return HTTP 400. A DTO that fails format conversion is not passed to its validator or to the handler. Parameters are resolved in order, so validation of an earlier DTO may already have run. For validation errors, `fields[].in` identifies the `body`, `path`, `query`, or `header` source.

The last request returns the OpenAPI JSON that you explicitly enabled. The document generator does not infer the page and size defaults applied inside the handler. See the [Runtime OpenAPI API](/en/reference/api/openapi) for configuration details and limitations.
