## Controllers and DTOs

```go
type UserPath struct {
	ID int64 `path:"id"`
}
type UserQuery struct {
	Name string `query:"name"`
}
type UserHeaders struct {
	RequestID string `header:"X-Request-ID"`
}
type CreateUser struct {
	Name string `json:"name" validate:"required"`
}

func (c *UserController) RegisterRoutes(r *api.Registry) {
	users := r.Group("/users", api.Interceptors((*Auth)(nil)))
	users.GET("/:id", c.Get)
	users.POST("/", c.Create)
}
func (c *UserController) Create(ctx spinectx.Ctx, body input.Body[CreateUser]) httpx.Response[CreateUser] {
	return httpx.Response[CreateUser]{Body: *body, Options: httpx.ResponseOptions{Status: 201}}
}
```

Use input.Path[UserPath], input.Query[UserQuery] and input.Header[UserHeaders] consistently. Bare *DTO HTTP inputs are rejected. Path/Query/Header default to lowerCamel names, overridden by tags. Body follows json/xml/form decoder rules. Only one success response is allowed; multiple responses and invalid or conflicting XML field tags fail preparation.

## Assembly and automatic validation

```go
engine, err := playground.New()
if err != nil {
	return nil, boot.Options{}, err
}
app := spine.New(echoplatform.Option(), spine.WithValidator(engine))
app.Constructor(
	constructor.Repository(&UserRepository{}),
	constructor.Service(&UserService{}),
	constructor.Controller(&UserController{}),
	constructor.Interceptor(&Auth{}),
)
```

Place this fragment in BuildApplication with the required types and imports. engine is the playground.New instance. Automatic tag validation needs no DTO Validate method. Implement additional methods yourself and call (*body).Validate() where needed; OpenAPI does not infer their bodies. app.Validate checks app configuration. Constructors support one return value and reject variadic parameters.

## Context and interceptors

Handlers and all hooks use pkg/spine.Ctx; direct standard context.Context injection remains compatible. Use ExecutionContext().Context() for DB/events, Set/Get for execution values, and public transport views for HTTP/WebSocket. Global and route PreHandle run before binding. BeforeResponse errors take response priority; HTTPError accepts only 400–599. AfterCompletion follows the write attempt and is not a commit point.

## CLI and compatibility code

Current generators should emit RegisterRoutes, role constructors and input wrappers. Check generated code with contract check, verify and actual HTTP requests. app.Route, route.WithInterceptors, query.Values, header.Values, path and multipart.UploadedFiles are deprecated compatibility APIs, not for new examples or generated code. Older migration pages describe their historical behavior; use this page for the current API.
