# Project Structure

Use the project generated by Spine CLI to separate application assembly from feature code. Complete [CLI installation](/en/learn/getting-started/installation) first.

## Create the project with CLI

Run this from the parent directory where you want to create the project.

```sh
spine version
spine new my-app --module example.com/my-app
cd my-app
go mod tidy
spine doctor
spine inspect
```

## Generated structure

`spine new` creates these files. `go mod tidy` creates `go.sum` afterward.

```text
my-app/
├── .gitignore
├── README.md
├── go.mod
├── main.go
├── spine.toml
└── internal/
    └── application/
        ├── application.go
        └── application_test.go
```

## CLI configuration

`module` must match `go.mod`. `entrypoint` selects the package to run or build; `composition` selects the source inspected for contracts and edited by automatic registration. Only these four configuration keys are supported. Keep application settings such as database connections separate.

```toml
module = "example.com/my-app"
entrypoint = "."
composition = "./internal/application"
port = 8080
```

## Separate startup from assembly

`main.go` builds, validates, and runs the application. Register constructors, routes, and interceptors inside `BuildApplication` in `internal/application/application.go`.

```go
package main

import (
    "log"

    "example.com/my-app/internal/application"
)

func main() {
    app, options, err := application.BuildApplication()
    if err != nil {
        log.Fatal(err)
    }
    if err := app.Validate(options); err != nil {
        log.Fatal(err)
    }
    if err := app.Run(options); err != nil {
        log.Fatal(err)
    }
}
```

The generated assembly function returns the application and runtime options without starting a listener. Its default HTTP route is `GET /health`.

```go
package application

import (
    "os"

    "github.com/NARUBROWN/spine"
    "github.com/NARUBROWN/spine/pkg/boot"
    "github.com/NARUBROWN/spine/pkg/httpx"
)

type HealthController struct{}

func NewHealthController() *HealthController { return &HealthController{} }

func (c *HealthController) Get() httpx.Response[map[string]string] {
    return httpx.Response[map[string]string]{Body: map[string]string{"status": "ok"}}
}

func BuildApplication() (spine.App, boot.Options, error) {
    app := spine.New()
    app.Constructor(NewHealthController)
    app.Route("GET", "/health", (*HealthController).Get)

    address := ":8080"
    if port := os.Getenv("SPINE_PORT"); port != "" {
        address = ":" + port
    }
    return app, boot.Options{Address: address, HTTP: &boot.HTTPOptions{}}, nil
}
```

## Add a feature with CLI

Generate a user resource from the project root. Skip this command if the resource already exists.

```sh
spine generate resource user
```

```text
src/user/
├── user_route.go
├── user_repository.go
├── user_service.go
└── user_controller.go
```

Automatic registration adds the following to `BuildApplication` by default. Check the generated result before adding registrations manually to avoid duplicates.

```go
if err := user.Register(app); err != nil {
    return nil, boot.Options{}, err
}
```

`user_route.go` registers the constructors and `GET /user/:id`. The controller handles HTTP input/output, the service owns business logic, and the repository owns data access. The resource generator creates only a GET skeleton that returns an ID; it does not implement a database model or persistence. For a typed create/read example, use a different name: `spine generate slice order --storage memory --field name:string`. Memory storage is for development and loses its data when the process stops.

## Registration rules and verification

Keep `app := spine.New()` at the top level of `BuildApplication() (spine.App, boot.Options, error)`. Keep registrations direct rather than placing them inside conditions, loops, or arbitrary helpers. Check and return errors from `Register(app)`.

```sh
spine contract check
spine verify
spine dev
```

`contract check` checks the static contract; `verify` checks the contract, gofmt, vet, and Go tests. Check database/broker connectivity and actual HTTP behavior separately.
